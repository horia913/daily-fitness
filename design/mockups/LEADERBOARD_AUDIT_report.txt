3 · DATA SOURCE, RANKING SCOPE, GRAVEYARD
------------------------------------------------------------------------------
Power: table public.leaderboard_entries (precomputed). No RPC for the board UI.
Populate: client-side service recalculates from workout_set_logs (PRs via calculatePRForExercise,
  tonnage via calculateTonnage), upserts rows, then recalcRanksForPartition (order by score desc).

Ranking scope (from query, not naming):
  GLOBAL across all clients present in leaderboard_entries for that
  (leaderboard_type, exercise_id, time_window) partition.
  No coach_id filter on read or rank. Not roster-scoped. Not challenge-scoped.
  (Prod sample: all 4 LB clients share one coach_id — leak not visible yet, but code allows it.)

Champions chip on client page: getCurrentChampions() reads rank=1 from leaderboard_entries
  (comment notes current_champions view / leaderboard_rankings path is unused for this).

Graveyard: live feature does NOT read graveyard.*. Dropping graveyard.leaderboard_titles
  (empty, unused) does not break this board. Uncertainty: whether any external/cron still
  expected to write leaderboard_rankings — none found in this repo.

------------------------------------------------------------------------------
4 · PRIVACY / CORRECTNESS
------------------------------------------------------------------------------
Exposed to any SELECT-capable client (RLS leaderboard_entries_select_all USING true):
  client_id, display_name, score, rank, leaderboard_type, exercise_id, is_anonymous, last_updated.

Visibility: profiles.leaderboard_visibility (public|anonymous|hidden).
  • Population skips upsert when hidden; anonymous → display_name "Anonymous".
  • updateLeaderboardVisibility() exists but has NO UI call site (client cannot change setting
    in-app; coach profile view only shows the field). All 13 profiles currently 'public'.
  • Hidden does NOT delete existing rows → stale public names/scores can linger. Uncertainty:
    whether admin/coach ever toggles visibility outside this app.

Cross-coach leak: YES by design of queries + RLS (global board). Mounting into coach Insights
  as-is would still show/compare athletes outside that coach's roster if they have entries.

Correctness notes:
  • Scores refresh on complete-workout / PR log-set / discard — event-driven, not cron.
    Stale risk if someone never completes after logging, or if visibility flips without
    recompute/delete. Not the athlete_scores cron path.
  • Sex filter re-ranks client-side after load (stored ranks can disagree with filtered order).
  • Exercise resolve uses name aliases; wrong exercise match → empty/wrong board (known alias map).
  • March 2026 audit ("never written") is STALE — population service + 158 live rows contradict it.
