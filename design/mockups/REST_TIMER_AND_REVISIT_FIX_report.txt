3) Auto-advance on revisit — root cause + gate
- Root cause: LiveWorkoutSetEntryExecutor.tsx useEffect (~L876–902) called
  onSetEntryComplete whenever a mounted block already had completedSets >=
  totalSets on the last exercise. Revisiting a done group remounts the executor
  with a fresh completedSetEntryRef, so the effect fired again →
  handleSetEntryComplete → 1.5s auto-advance timeout.
- Fix: removed that mount-time useEffect entirely. Block completion now only
  flows through handleSetComplete after an actual log (guarded by
  completedSetEntryRef in the logging path).
- Additional guard: handleSetEntryChange in start/page.tsx now clears any pending
  setEntryAdvanceTimeoutRef so manual navigation cannot be overridden by a
  stale auto-advance timer.
