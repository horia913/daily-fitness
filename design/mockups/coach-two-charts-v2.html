What's been added:
· Training phase bands in the background, from the program's own phases (Block 1 teal, Phase 2 orange) — so you can see which block a change happened in. Here adherence falls apart exactly at the Phase 2 boundary, which is the actual finding. The hover card names the phase too.
· Gradient area fills under the primary series, plus glow on the lines.
· Data-point dots at every week, so you can see where real data exists versus interpolation.
· Headline KPIs in the card header — current value, delta, and context — so the summary reads before you touch the chart. Adherence adds "sessions missed"; progression adds "records set · last week 7".
· An under-80% zone shaded red on the adherence chart, with an 80% guide line — a visible threshold rather than a number you have to compute.
· PR markers with stems connecting up to the top-set line, so a record reads against the lift that earned it.

Everything is still hand-rollable SVG — gradients, rects for bands, circles for dots. No chart library needed.

Phase bands need one thing confirmed: that program phases are queryable per week for a client (program_instance_phases exists). If a client has no phased program, the bands simply don't render.
