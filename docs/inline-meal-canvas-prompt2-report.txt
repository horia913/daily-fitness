## 2. Full-width fix

**What was clamping it:** The builder page wrapped content in `CoachPageShell widthVariant="default-5xl"`, which applies `max-w-5xl` (64rem). Coach Home (`/coach/page.tsx`) and the nutrition workspace (`/coach/nutrition/page.tsx`) both use `widthVariant="data-7xl"` (`max-w-7xl` / 80rem) for open data-dense tables.

**Fix:** Changed all builder `CoachPageShell` instances on `meal-plans/[id]/page.tsx` from `default-5xl` → `data-7xl`. **Page-level only** — `CoachPageShell.tsx` unchanged.

**Matches:** Nutrition workspace + Coach Home (`data-7xl`).

**Regression:** No shared-shell change; other routes using `default-5xl` unchanged. P4 `<1024px` macro 2×2 + legend and header stack unchanged (CSS media queries untouched).

## 3. Create custom food

**Reuses P2 contract:** `EMPTY_FOOD_CATALOG_FORM` / `FOOD_CATEGORIES` / `validateFoodCatalogForm` / `createFoodFromCatalogForm` — same fields as P2 `CoachFoodDatabasePanel` (name, brand, serving size/unit, calories, protein, carbs, fat, fiber, category). P2 panel now imports the same module.

**Catalog write vs draft:**
- `createFoodFromCatalogForm` → `MealPlanService.createFood(...)` writes to global `foods` **immediately** (catalog data).
- On success → `onSelect(food)` → P1 `onAddFood` / `addFoodToDraft` adds a **temp food row** to `workingCopy` (persists on tree **Save**).
- No deferral into `commitMealPlanTree`.

**Auto-add:** New food appears as a food row in the open option with default `quantity = serving_size`, `unit = serving_unit`.

**Where:** Food search dropdown footer `＋ Create "<query>"` / `＋ Create custom food` → expands `InlineCreateFoodForm` on canvas (not a modal).

## 4. Recents (quick-pick)

**Storage key:** `dailyfitness:meal-builder-food-recents`

**Mechanism:**
- Last **12** distinct `food_id`s, most-recent-first, deduped on each add (`recordRecentFoodId` on select/create).
- Persisted in `localStorage` across sessions (same pattern as P1 draft storage).

**Resolution:** `MealPlanService.getFoodsByIds(ids)` — single batch `foods` query with `.in('id', ids)`, ordered by recents list; missing/inactive foods silently omitted.

**Empty search UI:** When query length < 2, dropdown shows:
1. **Recent** group (required)
2. **In this plan** group (nice-to-have) — food ids from current `workingCopy`, excluding ids already in Recent

## 5. Keyboard shortcuts

**Guard:** `isTypingInField` — blocks when target is `HTMLInputElement`, `HTMLTextAreaElement`, or `contentEditable` (station checks input/textarea; contenteditable added per spec).

| Key | Action | Station analogue |
|-----|--------|------------------|
| **M** | Add meal in place (same as ＋ Add meal ghost row) | **N** = add exercise (station); **M** = add **m**eal |
| **F** | Open/focus food search on expanded meal's first option | — |

Shortcuts disabled on legacy read-only plans (`isLegacyPlan`).

**F behavior:** Requires a meal expanded (`openMealId`); opens food search on first option and focuses input via `MealListEditorHandle.openFoodSearch()`.
