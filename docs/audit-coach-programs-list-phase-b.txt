### Per-program meta shown (confirmed in `ProgramCard` + API)

| Field | Source | Shown in UI |
|-------|--------|-------------|
| **name** | `workout_programs.name` | Title |
| **difficulty_level** | `workout_programs.difficulty_level` | Badge / eyebrow (`beginner` \| `intermediate` \| `advanced` \| `athlete`) |
| **totalWeeks** | **Derived** — `SUM(training_blocks.duration_weeks)` via `getMasterProgramTotalWeeksBatch` (not `workout_programs.duration_weeks`) | "{n} weeks" pill |
| **assignment count** | Count of `program_assignments` rows per `program_id` (coach-scoped) | "{n} client(s) assigned" |
| **is_active** | `workout_programs.is_active` | "Inactive" in eyebrow when false; filter hides inactive unless "All" |
| **description** | `workout_programs.description` | Card body only (line-clamp-2); not in row layout |
| **target_audience** | API normalizes to `'general_fitness'` default | **Not displayed** on card |
| **created_at / updated_at** | Returned by API | **Not displayed** on list |

**Not shown on list (mockup also omits):** published/public status, periodization style, program type (fixed/recurring).

## PART 3 — Data & actions (post-spine)

### Data source

**List fetch:** `ProgramsDashboardContent.loadPrograms()` →  
`fetchApi(\`/api/coach/programs?filter=${active|all}\`)`  
(`src/app/api/coach/programs/route.ts`)

**Queries (confirmed in route):**

1. `workout_programs` — `select('*')`, `coach_id = user.id`, optional `is_active = true`, `order by created_at desc`
2. `program_assignments` — `select('program_id')`, `coach_id = user.id` → aggregated to `assignmentCountByProgram`
3. `training_blocks` — batch via `getMasterProgramTotalWeeksBatch()` (`src/lib/programs/masterProgramWeeks.ts`) → `totalWeeks` per program

**Response shape per program:** spread of `workout_programs` row + `totalWeeks: number` + `target_audience` default.

### Page-level actions

| Action | Trigger | Calls / navigates |
|--------|---------|-------------------|
| **Refresh** | Header button | `loadPrograms()` (re-fetch API) |
| **Create program** | Header link | `href="/coach/programs/create"` |
| **Filter Active / All** | Pills | `setProgramFilter` → re-fetch with `filter=active\|all` |

### Per-row actions (via `ProgramCard` callbacks)

| Action | UI | Behavior |
|--------|-----|----------|
| **View** | Eye / card click | `window.location.href = /coach/programs/${id}` → **legacy detail page** |
| **Edit** | Edit icon | `window.location.href = /coach/programs/${id}/edit` → **station** |
| **Assign** | UserPlus icon | `openAssignModal(programId)` — inline modal in `ProgramsDashboardContent` |
| **Delete** | Trash icon | Delete modal → `WorkoutTemplateService.deleteProgram(id)` |

**Not on list:** Duplicate (only on `/coach/programs/[id]` detail page via `POST /api/coach/programs/[id]/duplicate`).

### Assign path — FENCE (logic untouched in Phase B)

**Entry:** `openAssignModal` → user selects clients → `submitAssign` → optional replace confirm → `doAssignAndClose`.

**Core logic (do not change in presentation rebuild):**

```text
WorkoutTemplateService.assignProgramToClients(
  programId, clientIds, coachId, startDate, notes, progressionMode
)
  → per client: supabase.rpc('assign_program_instance', { … })
```

(`src/lib/workoutTemplateService.ts` L1448–1505)

**Supporting logic (also fenced):**

- `WorkoutTemplateService.getClientsWithActiveProgram(clientIds)` — replace-confirm modal
- Client list load: direct `supabase.from('clients')` + `profiles` merge in `openAssignModal`
- Progression mode: `'auto' | 'coach_managed'` passed to RPC

**Delete path (fenced):** `WorkoutTemplateService.deleteProgram` — soft-delete `workout_programs.is_active = false` (L1174–1186).

**Create path (fenced, separate route):** `/coach/programs/create` → `WorkoutTemplateService.createProgram` → redirect to station.

### Presentation/logic tangle note

Assign, replace-confirm, and delete modals are **~300 lines inline** in `ProgramsDashboardContent.tsx` (L462–755) with bordered inputs, blur scrims, and semantic gradient buttons. Phase B can restyle these shells but must not alter `submitAssign` / `doAssignAndClose` / `handleDelete` orchestration or RPC payloads.

## PART 6 — Judgment: reskin vs rebuild, reuse, fences

### Verdict: **Structural rebuild** (not a reskin)

Cards → open table changes DOM structure, responsive behavior (desktop table + mobile stack), and action placement. This matches nutrition Phase B (meal plans cards → `CoachMealPlansPanel` table). Presentation-only, but **layout is new**, not token swap on existing cards.

### Reusable as-is (or with styling only)

| Asset | Notes |
|-------|-------|
| **`GET /api/coach/programs`** | Returns all fields needed for mockup columns |
| **`ProgramsDashboardContent` state** | `programs`, `assignmentCountByProgram`, `programFilter`, loading/error |
| **Assign modal flow** | Client search, date, notes, progression mode, replace confirm — **restyle shell only** |
| **Delete modal flow** | Confirm checkbox + soft delete — **restyle shell only** |
| **Links** | Edit → `/coach/programs/[id]/edit` (station); Create → `/coach/programs/create` |
| **`ProgramCard` action mapping** | Logic reference for View/Assign/Edit/Delete — component likely **replaced** by table row, not reskinned |

### Must fence (logic untouched)

| Fence | Location |
|-------|----------|
| `assign_program_instance` RPC via `assignProgramToClients` | `workoutTemplateService.ts` |
| `getClientsWithActiveProgram` + replace confirm branching | `ProgramsDashboardContent.submitAssign` |
| `deleteProgram` soft-delete | `workoutTemplateService.ts` |
| `GET /api/coach/programs` route + `getMasterProgramTotalWeeksBatch` | API + lib |
| Create program (`createProgram` + redirect) | `/coach/programs/create` — out of list scope but linked |

### Route-consolidation recommendations (future, not Phase B)

1. **`/coach/training/programs`** — docs reference it; **no route exists**. Update docs; hub already points to `/coach/programs`.
2. **`/coach/programs-workouts`** — **absent**; retire from docs/nav inventories.
3. **`/coach/programs/[id]` detail vs station** — mockup includes **View** separate from Edit. Detail page is legacy schedule grid; consider whether View → station read-only, detail page demotion, or keep detail for "preview without editor". **Product decision** — flag for follow-up.
4. **`/coach/programs/new`** — harmless alias; optional merge into create only.

### Tangling risks

| Risk | Mitigation |
|------|------------|
| Assign/delete modals embedded in list component | Extract **presentation** subcomponents; keep handlers in parent |
| `window.location.href` for navigation | Can switch to `router.push` in rebuild (behavior-neutral) |
| Duplicate only on detail page | Mockup doesn't show duplicate on list — OK to omit on table |
| Mobile: mockup is table-only | Follow nutrition pattern: `.tableRowDesktop` / `.tableRowMobile` collapse @ `<1024px` |

### Suggested Phase B approach (audit-only recommendation)

1. New presentation module (e.g. `CoachProgramsWorkspace` + `coachProgramsWorkspace.module.css`) mirroring `CoachNutritionWorkspace` / `CoachMealPlansPanel`.
2. Keep `ProgramsDashboardContent` data/handlers or slim it to a thin container — **fence** assign/delete/create orchestration.
3. Replace `ProgramCard` grid with open table; borrow nutrition table CSS tokens.
4. Shell: align with nutrition (`data-7xl`) or builder (`canvas-full`) per product — mockup reads full-width inside training main.
5. Do **not** import station draft context into list.
