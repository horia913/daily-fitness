3. PER-SET PRESCRIPTION VERDICT
================================================================================

VERDICT: **PARTIALLY reach** — stored and likely returned by RPC, **lost before UI renders**

3.1 Storage granularity (live DB confirmed via information_schema)
  Per-set tables (one row per set_number per slot):
    program_instance_set_prescriptions  (instance / program days)
    workout_set_prescriptions           (templates)
  Columns per row: slot_id, set_number, reps, weight_kg, load_percentage, rir, tempo,
                  work_seconds, distance_meters
  Rest is NOT per prescription row — lives on slot (rest_seconds) or group (rest_seconds).

  Per-exercise slot table also has scalar fallbacks (often mirror set 1):
    program_instance_set_entry_exercises / workout_set_entry_exercises
    (sets, reps, weight_kg, rir, tempo, technique, drop_*, cluster_*, etc.)

  Coach canvas writes per-set rows (PrescriptionTable.tsx — one input row per set_number).

3.2 Delivery from loader
  Intermediate: canvasLoadRpcMapper.ts:43-48 maps row.prescriptions[] from RPC payload when present.
  So prescriptions likely survive **into CanvasExercise.prescriptions** inside get_instance_workout_canvas response.

3.3 Break points (code evidence)

  BREAK #1 — instanceWorkoutBlocksMapper.ts:37-48
    const firstRx = slot.prescriptions?.[0]
    Only firstRx copied to exercise scalars (reps, weight_kg, rir, tempo, …).
    prescriptions array passed on slot row but…

  BREAK #2 — toLegacyBlockShape.ts mapSlotToExercise:22-52
    Builds WorkoutSetEntryExercise from slot scalars only.
    Never reads slot.prescriptions[].

  BREAK #3 — start/page.tsx clientBlocks mapping:2025-2045
    Maps exercises without prescriptions field.

  BREAK #4 — WorkoutSetEntryExercise type (workoutSetEntries.ts:51-78)
    No prescriptions[] on the type executors receive.

  BREAK #5 — Executors (e.g. StraightSetExecutor.tsx:177-180, 423-425)
    One repsDisplay / prescribedRepsDefault for all set rows.

  Standalone get_workout_blocks path: workoutBlocksRpcMapper.ts:5-6 explicitly ignores
  satellite/prescription arrays; same legacy flatten via adaptRpcBlockToLegacy.

3.4 Live example (instance workout — confirms break has user-visible effect)
  Popescu instance 3e54eac4-… exercise CMJ:
    set_number 1: rx weight 5 kg; sets 2-3: rx weight null (DB)
  UI would show exercise.weight_kg from firstRx only and identical reps "3" on every row.

3.5 Technique / rest per set
  technique, drop_percentage, cluster params: slot-level only (not per prescription row).
  Per-set tempo/RIR/weight/reps: in DB per row, flattened to set-1 only at BREAK #1.
