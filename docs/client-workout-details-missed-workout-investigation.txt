4.1 Workout-details failure (H2 — code fix direction)
--------------------------------------------------------------------------------

Preferred fix: align Train link with spine identity.

  Option A (smallest): TrainWeekDayList "Open workout" uses schedule-based route:
    /client/program-days/${day.scheduleId}/details  (new or existing)
    Resolve content from program_day_assignments + instance/template meta.

  Option B: Keep URL shape; extend details page load():
    If workout_assignments miss, try program_instance_workouts by id for active assignment
    OR program_day_assignments where program_instance_workout_id = id and client owns assignment.
    Load blocks via loadDayExerciseGroups / loadWorkoutBlocksByContentId pattern
    (instance-first), not assignment.workout_template_id-only path.

  Option C: Only link after start — "Open workout" goes to workout_assignment created by
    start-from-progress bridge. Poor UX for preview-before-start.

Do NOT pass day.templateId to a route that only understands workout_assignments.id /
workout_templates.id when templateId is program_instance_workout_id.

Fold vs fix legacy route:
  Worth fixing preview for program slots — users expect details before starting missed work.
  Can share loader with loadDayCanvas.ts (already instance-aware).
