PART 1 — MAXIMUM A COACH CAN PRESCRIBE (design input)
================================================================================

1.1 Per-set prescription fields (schema + canvas UI)
----------------------------------------------------
DB tables (identical shape):
  program_instance_set_prescriptions  (instance path)
  workout_set_prescriptions           (template path)
Columns (information_schema, live):
  slot_id, set_number,
  reps (varchar), weight_kg, load_percentage, rir, tempo,
  work_seconds, distance_meters
  — NO rest_seconds column on prescription rows.

Independently settable PER SET (canvas PrescriptionTable + schema):
  reps | work_seconds | distance_meters  (one primary measurement column per row, driven by slot.measurement)
  load: weight_kg OR load_percentage (mutually exclusive per row edit — PrescriptionTable.tsx:174-191)
  rir, tempo

Per-set NOT in schema / canvas table:
  rest (slot-level rest_after_exercise or group rest_seconds only)
  technique params (drop %, cluster reps, pause seconds — slot-level, see 1.2)
  drop chain rows: coach CAN add multiple prescription rows; for drop_set technique, extra rows represent drop steps (buildSegments.ts:94-115 uses rows.slice(1) as drop chain)

Canvas add-set rule: only when rounds_driver is fixed or for_time (PrescriptionTable.tsx:46,317-320).

1.2 Exercise-level (slot) fields
--------------------------------
program_instance_set_entry_exercises / workout_set_entry_exercises:
  exercise_id, exercise_order, exercise_letter
  measurement: reps | time | distance (NOT NULL, default reps)
  technique: text NOT NULL default 'none' (canvas types: none | drop_set | cluster | rest_pause — types.ts:5)
  sets, reps, weight_kg, load_percentage, rir, tempo, rest_seconds, notes
  work_seconds, distance_meters
  target_time_seconds, target_pace_seconds_per_km, target_speed_pct
  hr_zone, target_hr_pct
  drop_percentage, max_drops
  reps_per_cluster, clusters_per_set, intra_cluster_rest_seconds
  rest_pause_seconds, max_rest_pauses
  is_optional (slot-level boolean)

Canvas enabledProperties (session + persisted when values exist): load, rir, tempo, rest_after_exercise, drop_set, cluster, rest_pause (propertyLabels.ts:17-18).

1.3 Group / set-entry level
---------------------------
program_instance_set_entries / workout_set_entries:
  set_order, set_name, set_notes
  set_type (legacy enum; canvas derives this — see drift)
  total_sets, reps_per_set, rest_seconds, duration_seconds
  rounds_driver: fixed | amrap | interval | for_time (types.ts:3; WorkoutCanvas.tsx:449-452)
  interval_seconds (EMOM/interval)
  time_cap_seconds (for_time)
  is_optional (group-level; used in program week compliance, NOT executor skip UI)

Multi-exercise groups: unlimited slots in canvas (CanvasGroup.slots[] — canvasTypes.ts:47; DnD in WorkoutCanvas.tsx:458+). deriveSetType:
  2 slots + all time → tabata
  2 slots + reps → superset
  3+ slots → giant_set (deriveSetType.ts:37-40)

Live instance data today: max 2 slots per group observed; 0 groups with 3+ slots. Capability exists; not exercised in prod data.

rounds_driver live counts (program_instance_set_entries): fixed=435, amrap/interval/for_time=0. Canvas supports all four; prod instance content is 100% fixed rounds.

1.4 Techniques / protocols — physical behavior + config + reachability
--------------------------------------------------------------------
CANVAS-REACHABLE (coach UI + deriveSetType + toLegacyBlockShape):

| Derived set_type | How coach configures | Client physical behavior | Config data |
|------------------|----------------------|--------------------------|-------------|
| straight_set | 1 slot, reps, fixed rounds | N sets × reps, rest between sets | per-set rx + slot/group rest |
| superset | 2 slots, fixed rounds | Alternate A→B per round; one log per round | exercise_letter A/B; total_sets = rounds |
| giant_set | 3+ slots | All exercises per round; one log per round | letters A/B/C…; giant_set_exercises JSON log |
| drop_set | slot technique drop_set | Initial weight/reps then reduce weight within set | drop_percentage, max_drops; multi-row rx = drop chain |
| cluster_set | slot technique cluster | Weight × clusters × reps/cluster with intra-rest | reps_per_cluster, clusters_per_set, intra_cluster_rest_seconds |
| rest_pause | slot technique rest_pause | Initial reps, brief pause, more reps same weight | rest_pause_seconds, max_rest_pauses |
| amrap | rounds_driver amrap | Max reps in duration | duration_seconds, per-set reps/load |
| emom | rounds_driver interval | Work each interval_seconds for duration | interval_seconds, duration_seconds |
| for_time | rounds_driver for_time | Complete work under cap | time_cap_seconds, per-set reps |
| tabata | 2+ slots all measurement=time | Timed work/rest alternation | work_seconds per slot, total_sets rounds |
| timed_set | 1 slot measurement=time | Sets × work_seconds | work_seconds per row |
| speed_work | 1 slot distance, total_sets>1 | Repeated distance intervals | distance_meters rows, target_speed_pct, target_pace… |
| endurance | 1 slot distance, total_sets=1 | Continuous distance target | distance_meters, hr_zone, target_time_seconds |

DEAD / NOT CANVAS-REACHABLE (Postgres workout_set_type enum but NOT in deriveSetType or canvas):
  pyramid_set, ladder, emom_reps, circuit, hr_sets (pg_enum query; deriveSetType.ts has no branches)

pre_exhaustion: enum + PreExhaustionExecutor exist; canvas maps 2-slot groups to superset (deriveSetType comment line 13; mapCanvasToExerciseDisplay.ts:88).

Live technique counts (program_instance_set_entry_exercises): none=399, drop_set=41, cluster=0, rest_pause=0.

2.4 Logging path
----------------
Tap flow (straight set, typical):
  1. Edit weight/reps in SetRowShell row (or ± steppers in row fields)
  2. Tap round check / log button on row (SetRowShell 51-58) OR LogSetButton in legacy single-set path
  3. Optional: "Fill remaining with target" (SetRowsListPanel 17,45; useSetRowsState fillRemaining)
  4. useSetLoggingOrchestrator.logSet → sessionStorage idempotency (goldenLogSet.ts)
  5. Background POST /api/log-set → buildLogSetInsertData (per set_type) → workout_set_logs
  6. Inline RPE: LoggedSetsList "How hard was that?" + SetEffortPicker (LoggedSetsList 10-11)
  7. RestTimerModal (orchestrator shouldOpenRestTimer — parallel to sync, not gated)

workout_set_logs shape: wide type-specific columns (set_number, weight, reps, rpe, superset_*, giant_set_exercises jsonb, dropset_*, cluster_number, rest_pause_*, amrap_*, emom_*, etc.) — schema query above.

Interactions to log one straight set (row-based path): ~3-6 taps (weight adjust, reps adjust, log, optional RPE tier, optional dismiss rest timer).

RPE: stored on workout_set_logs.rpe; inline per logged row (not modal — useSetLoggingOrchestrator showRpeModal deprecated line 62-63).

2.5 Superset / giant-set handling
---------------------------------
Superset: presents both exercises in one block; logs one workout_set_logs row per round with superset_exercise_a/b fields (buildLogSetInsertData 73-85). NOT sequential separate blocks. Does NOT show A1/A2 badges in header — uses combined title or "EXERCISE 1 OF 2" hint (BaseBlockExecutor 129-132). exercise_letter in DB (e.g. Kettlebell Swing A / Mountain Climber B — live fb7ca0ee…) not shown as Element 15 badges.

Giant set: round-based logging (round_number + giant_set_exercises array). exercise_letter used only in row labels (GiantSetExecutor 766).
