## 2. Target-set criteria, cap, error handling

### Recompute targets (all must hold)

| Criterion | Implementation |
|-----------|----------------|
| Stale | `scoreIsStale === true` (existing `computeScoreIsStale(athleteScore, lastActive)`) |
| Active program | `hasActiveProgram === true` |
| Not paused | `pauseStatus !== 'paused'` |
| Throttle | `athleteScore.calculated_at` at least **1 hour** old (`scoreCalculatedBeforeOneHourAgo`) — mirrors `GET /api/client/athlete-score` |
| Cap | First **5** matching clients in roster order (`STALE_SCORE_RECOMPUTE_CAP = 5`) |

### Per-target behavior

- `await calculateAthleteScore(clientId, supabaseAdmin)` with service-role client (same pattern as cron/discard).
- **Success** (`skipped: false`): replace `athleteScore` with `{ score, tier, calculated_at, paused }` and set **`scoreIsStale = false`**.
- **Skipped** (`no_program` / `paused` / `no_data`): log `console.warn`, keep prior `athleteScore` + `scoreIsStale` (UI stays "—").
- **Thrown error**: log `console.error`, keep prior values — **list response never fails** on recompute.

Recompute runs only when `SUPABASE_SERVICE_ROLE_KEY` and `NEXT_PUBLIC_SUPABASE_URL` are set.
