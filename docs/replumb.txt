2. WHERE PER-SET RESOLUTION LANDED
================================================================================
Shared point (preferred):
  resolveSetPrescriptionTargets(exercise, setNumber) — match by set_number
  resolveSetRowWeightDefault({ ..., prescribedWeightKg }) — weight hierarchy entry

Wired into the 4 executors that use useSetRowsState + SetRowShell row prefills
(Straight / Superset / Giant / Drop). Those are the only surfaces that show
"one target per set row" today.

Other 9 executors (Amrap, Emom, Tabata, ForTime, Cluster, RestPause, Timed,
Speed, Endurance, PreExhaustion) do not use that shared row-prefill path;
they keep scalar / protocol-specific UIs. No bespoke edits there.

LiveWorkoutSetEntry uses WorkoutSetEntry → WorkoutSetEntryExercise, so the
type addition covers the live path without a separate Live exercise type.

================================================================================
3. PREFILL HIERARCHY (as implemented)
================================================================================
Per field for set N (resolveSetPrescriptionTargets):
  1. prescriptions.find(p => p.set_number === N).field  when non-null / non-empty
  2. exercise-level scalar (reps, weight_kg, load_percentage, rir, tempo)
     — reps also falls back to block.reps_per_set
  3. null → caller continues

Weight row prefill (resolveSetRowWeightDefault):
  1. prescribedWeightKg (from step above, includes exercise scalar if rx null)
  2. last-session weight for that set_number (unchanged)
  3. previous row weight when set > 1 (unchanged)
  4. session sticky / defaultWeight (unchanged)
  5. suggestedWeight (unchanged)
  6. blank

Reps row prefill: parseRepsTarget(targets.reps).numericDefault when > 0,
else previous row — same as before, but source is per-set targets.

Null per-set values (e.g. CMJ set 2–3 weight null) fall through to exercise
scalar / last-time / blank — never hard-copied from set 1's prescription row.
