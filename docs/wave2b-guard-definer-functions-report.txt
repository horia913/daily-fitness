================================================================================

1. create_user_profile(uuid, text, text)
   - No .rpc('create_user_profile') in src/. Signup uses auth trigger
     handle_new_user() which INSERTs profiles directly (confirmed live).
   - SQL adds auth.uid() = user_id guard + REVOKE from PUBLIC/anon.
   - If any external tool still calls this RPC with service role, it will fail
     after REVOKE unless called as service_role (still has EXECUTE).
   - Action: safe to apply; function appears legacy.

2. complete_workout — app/code signature mismatch (informational, not a blocker)
   - Live DB: complete_workout(p_assignment_progress_id, p_week_number,
     p_program_day, p_template_id, ...)
   - src/lib/workoutTemplateService.ts:1673 passes p_client_id, p_template_id
     (different signature — likely dead/stale client path).
   - Guard added on live signature via program_assignment_progress.client_id.
   - Browser test: modern completion uses completeWorkoutService / API routes,
     not this RPC with old params.

3. get_client_compliance_scores / _simple — query body still lacks coach roster
   filter (pre-existing logic bug). Guard only enforces coach_id_param = auth.uid().
   Coach A cannot impersonate Coach B, but may still see global client rows if the
   underlying query returns them. Fixing the query is out of scope (minimal diff).
   Note for follow-up: add AND EXISTS (... clients c WHERE c.client_id = p.id
   AND c.coach_id = coach_id_param) to both functions.

4. Session booking RPCs (book_session, cancel_session, complete_session,
   add_session_feedback) — no .rpc() references in src/ (grep 2026-07-10).
   Guards added for defense-in-depth; no browser test path unless booking UI
   calls them from an ungrepped path.

5. deactivate_previous_program — no src/ .rpc() caller; likely invoked from
   assign_program_instance or manual SQL. Guard: coach must own p_client_id.
